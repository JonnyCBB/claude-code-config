# Checklist

Condensed form of the method. Run the pre-flight before opening any engine; run the pre-delivery before reporting.

## Pre-flight — before pricing anything

- [ ] **Option space derived from the rules**, written out, and diffed against any grid/shortlist I was handed. Differences stated to the user.
- [ ] **Candidate list checked for completeness** — are there qualifying candidates outside the inherited shortlist?
- [ ] **Disqualifying screens run** — safety, eligibility, hard requirements, availability. Eliminated candidates not priced.
- [ ] **Reconnaissance pass done across every provider** — one candidate, one config, all providers.
- [ ] **Inclusions matrix built** from each provider's own "what's included", not from assumption or brand.
- [ ] **URL template captured per provider**, with the parameter for each variable identified.
- [ ] **Highest-variance axis identified**, and the cheapest way to sweep it (calendar, grid, matrix view).
- [ ] **Display units confirmed** — per-person or total — and how to verify after navigation.

## During capture

- [ ] Storing **everything the source returns**, not just the cells the output needs.
- [ ] **Reading back applied parameters** after every search — dates, duration, party, spec — before recording.
- [ ] Recording **source URL, retrieval date, inclusions, exact spec** with each figure.
- [ ] Recording the **exact listed name** alongside my canonical name; identity confirmed by a second signal.
- [ ] Failed lookups → **cell blank + gap entry with a retry URL**. No estimates anywhere.
- [ ] Any figure from a **different configuration than requested** is flagged, not silently substituted.

## Pre-delivery

- [ ] Every row either has a real figure **or** a logged gap. No silent blanks.
- [ ] It is **visible in the artefact** which prices are landed totals and which omit components.
- [ ] **Ranking-inverting attributes checked** on the leading candidates — the quality dimension a cheaper option might be cheaper _for_.
- [ ] **Hard gates confirmed** on the front-runner. A candidate failing a stated dealbreaker is not a front-runner.
- [ ] Figures **date-stamped** and described as snapshots, not quotes.
- [ ] Report **leads with what changes the decision**, not with volume of work.
- [ ] Uncomfortable conclusions stated plainly rather than padded around.
- [ ] Open questions each have a **specific next action**.

## The four failures this exists to prevent

1. **Incomparable comparison** — ranking headline prices that bundle different things.
2. **Truncated option space** — pricing only what someone already listed.
3. **Schema-shaped capture** — letting the output format decide what evidence survives.
4. **Invented numbers** — an estimate that reads like a retrieved price.
